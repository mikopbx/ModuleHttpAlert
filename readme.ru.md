Модуль позволяет настроить "HTTP хуки" (реакции) на события:
 - Поступление звонка в компанию
 - Поступление звонка на сотрудника
 - Ответ на вызов
 - Завершение звонка

Модуль можно подгрузить в разделе "**Модули**" - "**Маркетплейс модулей**" - "**Загрузить новый модуль**" - выбрать файл ZIP архива.

На главной странице настроек предложено описать "**Базовый URL**" - адрес сервера, что будет принимать HTTP GET запросы. 
 * Для каждого DID можно задать свой базовый URL. 
 * Если DID не описан, то этот базовый урл будет использован "по умолчанию". 
 * Пример URL `http://127.0.0.1/pbxcore/api/module-http-alert/v1/test`

После установки модуля следует его включить и перейти к редактированию настроек:

При нажатии на кнопку `"Изменить параметры модуля"` можно заполнить отправляемые параметры для каждого собития. 
Пример: поле "**Параметры URL. Вызов поступил на АТС.**":

`
date=<date>&id=<id>&uid=<uid>&number=<number>&channel=<channel>&did=<did>&action=<action>
`

При появлении нового входящего звонка будет отправлен **GET** запрос на указанный **Базовый URL**. 
Если сервер вернул код ответа `200` и `текст`, то `текст будет установлена в качестве caller id name` для этого звонка.  

В скобках задаются параметры запроса, они будут заменены при отправке на сервер.
 - "date" - дата звонка 
 - "id" - уникальный идентификатор звонка - по нему можно отфильторвать историю звонков в соответствующем разделе web интерфейса АТС
 - "uid" - уникальный идентификатор CDR (история звонков) на АТС
 - "number" - номер телефона звонящего
 - "channel" - идентификатор канала на АТС
 - "did" - номер, который набрал клиент, часто совпадает с логином SIP провайдера (см. статью https://wiki.mikopbx.ru/faq:did-routs)
 - "action" - значение всегда равно строке "incoming-call"
В разделе "**Обслуживание**" - "**Системные логи**" на вкладке "**Просмотр логов**" доступен файл "`ModuleHttpAlert/ListenerAMI.log`"

Другой пример указания параметров для URL:

`Identifier=<did>&Number=<number>`

В этом логе при поступлении входящего звонка отобразится строка:

`
[2023-10-25T13:10:10+03:00][info] {"1":{"date":"2023-10-25T13:10:10 03:00","id":"mikopbx-1698228609.369","uid":"mikopbx-1698228610.373_een3wt","number":"79257181233","channel":"PJSIP/SIP-1692280724-0000007c","did":"1233","action":"incoming-call"}}
`

В ней перечислены все, описанные выше, параметры, применяемые при GET запросе к внешней системе.

Если в качестве URL указать "`http://127.0.0.1/pbxcore/api/module-http-alert/v1/test`", то в системном логе "system/messages" будет доступна строка:

`
Oct 25 13:10:10 daemon.info php.frontend[11725]:  {"date":"2023-10-25T13:10:10+03:00","id":"mikopbx-1698228609.369","uid":"mikopbx-1698228610.373_een3wt","number":"79257181233","channel":"PJSIP\/SIP-1692280724-0000007c","did":"1233","action":"incoming-call"} on ModuleHttpAlert
`

Фактически в системный лог выводятся все параметры, что были переданы в GET запросе к локальному серверу. Лог можно отфильтровать по строке "`ModuleHttpAlert`" или по строке "`incoming-call`".
