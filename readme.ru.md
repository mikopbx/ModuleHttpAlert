## HTTP Alert — уведомления о звонках для вашего сайта и CRM

Модуль связывает вашу АТС MikoPBX с CRM, сайтом или любой другой программой. Как только на телефон поступает звонок, модуль мгновенно сообщает об этом вашей системе — и она может, например, показать сотруднику карточку клиента ещё до того, как он снимет трубку.

**Что умеет модуль:**

- 🔔 Сообщает о каждом важном событии: входящий звонок, звонок на сотрудника, ответ на вызов, завершение разговора.
- 👤 Показывает имя клиента на телефоне — если ваша CRM знает, кто звонит, его имя автоматически появится на экране.
- 🎯 Гибкая настройка под каждый номер — для разных входящих линий можно указать разные адреса и параметры.
- ⚙️ Работает «из коробки» — никакого программирования, всё настраивается в простом и понятном интерфейсе.

**Зачем это нужно:**
Ускоряет работу операторов, помогает не терять клиентов, делает обслуживание звонков персональным. Идеально для интеграции телефонии с CRM, отделом продаж и службой поддержки.

## Техническая информация

### Принцип работы

Модуль отправляет **HTTP GET-запросы (вебхуки)** на указанный вами сервер при событиях телефонии:

- **Вызов поступил на АТС** — `action = incoming-call`
- **Вызов поступил на сотрудника** (набор)
- **Ответ на вызов**
- **Завершение звонка**
- **Запись в истории звонков (CDR)**

Если в ответ на входящий звонок сервер вернёт код `200` и текст — этот текст подставляется в качестве **Caller ID Name**.

### Настройка URL

В настройках указывается **Базовый URL** — адрес сервера, принимающего запросы. Для каждого DID можно задать собственный базовый URL и HTTP Basic Auth; если DID не описан — используется URL «по умолчанию» (с пустым DID).

Пример: `http://127.0.0.1/pbxcore/api/module-http-alert/v1/test`

### Параметры запроса (плейсхолдеры)

Параметры события задаются шаблоном, плейсхолдеры заменяются реальными значениями при отправке:

| Плейсхолдер | Значение |
|---|---|
| `<date>` | дата звонка |
| `<id>` | уникальный идентификатор звонка |
| `<uid>` | идентификатор записи CDR (история звонков) |
| `<number>` | номер телефона звонящего |
| `<channel>` | идентификатор канала на АТС |
| `<did>` | набранный номер / DID (часто совпадает с логином SIP-провайдера) |
| `<action>` | тип события (напр. `incoming-call`) |
| `<user>`, `<client>` | дополнительные значения |

Пример шаблона:

`date=<date>&id=<id>&uid=<uid>&number=<number>&channel=<channel>&did=<did>&action=<action>`

Другой пример:

`Identifier=<did>&Number=<number>`

При поступлении входящего звонка будет отправлен **GET**-запрос на **Базовый URL** с подставленными значениями. Подробнее о DID см. статью https://wiki.mikopbx.ru/faq:did-routs

### Архитектура

- **ListenerAMI** — фоновый воркер, слушает события Asterisk через AMI, определяет тип звонка (входящий/исходящий/внутренний) и ставит задачи в очередь.
- **WorkerHTTP** — обрабатывает HTTP-запросы через очередь Beanstalk с ограничением **7 запросов/сек**.
- **AGI-скрипт** — срабатывает на входящем звонке до набора, может установить Caller ID Name.
- **safe.php** (cron) — следит за воркерами и перезапускает упавшие.
- HTTP-клиент на базе **Guzzle**, timeout 5 сек.

### Установка и требования

- Установка через раздел **Модули → Маркетплейс модулей → Загрузить новый модуль** (ZIP-архив).
- После установки модуль нужно **включить** и перейти к редактированию настроек.
- Минимальные требования: **PHP 7.4.6**, **MikoPBX Core ≥ 2023.2.160**.

### Логи и отладка

Запросы пишутся в `ModuleHttpAlert/ListenerAMI.log` (раздел **Обслуживание → Системные логи → Просмотр логов**). Пример строки лога при входящем звонке:

`[2023-10-25T13:10:10+03:00][info] {"1":{"date":"2023-10-25T13:10:10+03:00","id":"mikopbx-1698228609.369","uid":"mikopbx-1698228610.373_een3wt","number":"79257181233","channel":"PJSIP/SIP-1692280724-0000007c","did":"1233","action":"incoming-call"}}`

Встроенный тестовый endpoint `GET /pbxcore/api/module-http-alert/v1/test` выводит все параметры запроса в системный лог `system/messages` — удобно для проверки вебхуков. Лог можно отфильтровать по строке `ModuleHttpAlert` или `incoming-call`.
